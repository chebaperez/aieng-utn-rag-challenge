1. Cómo evalúa el benchmark

Cada caso del dataset contiene una pregunta financiera, una tabla, una lista de párrafos narrativos y el Ground Truth (GT) esperado. Tu sistema agéntico debe responder un objeto CaseOutput con:

  • verdict: "SOLVED" si encontró evidencia suficiente para calcular la respuesta, o "ABSTAIN" si falta información indispensable.
  • primary_value: número finito cuando verdict == "SOLVED", o null cuando verdict == "ABSTAIN".
  • scale: unidad de magnitud (null, "thousand", "million", "billion" o "percent").
  • derivation: fórmula o expresión aritmética utilizada para llegar al valor.
  • execution_trace: pasos de herramientas ejecutados (al menos 1 paso si verdict == "SOLVED").
  • usage: contadores reales de tokens (prompt_tokens + completion_tokens == total_tokens) y llm_calls.

2. Estados de evaluación y puntuación asimétrica

El evaluador premia las respuestas correctas, no penaliza abstenerse cuando corresponde (y es neutro ante una abstención cautelosa), pero castiga las alucinaciones y errores numéricos o de contrato:

Estado Puntaje Cuándo ocurre Ejemplo típico
CORRECT +1.0 SOLVED en caso resoluble, escala compatible y valor dentro de tolerancia. GT: -5.934 percent · Pred: -5.934 percent
ABSTAIN_ON_UNSOLVABLE 0.0 ABSTAIN correcto sobre un caso sin evidencia suficiente. GT: ABSTAIN · Pred: ABSTAIN
ABSTAIN_CAUTIOUS 0.0 El agente se abstuvo, pero el caso sí era resoluble (dejó +1.0 pt sin ganar). GT: SOLVED (19213) · Pred: ABSTAIN
WRONG_VALUE -1.0 El valor normalizado excede la tolerancia respecto del Ground Truth. GT: 19213 · Pred: 12345 (error de extracción o cálculo)
SCALE_MISMATCH -1.0 Se mezcló "percent" con una escala de magnitud (o viceversa). GT: 15.4 percent · Pred: 15.4 million
HALLUCINATION_ON_ABSTAIN -1.0 El agente respondió SOLVED en un caso cuyo GT es ABSTAIN. GT: ABSTAIN · Pred: SOLVED (42.0)
TIMEOUT 0.0 Tiempo de espera agotado (>90s) sin respuesta del endpoint (aislado de SCHEMA_ERROR). Latencia excede 90s bajo carga o generación extensa
SCHEMA_ERROR -1.5 Falta la predicción, falló el contrato Pydantic o hubo error HTTP (5xx/conexión). primary_value: null con verdict: "SOLVED"

3. Normalización de escalas y tolerancia numérica

  • Magnitudes (null, "thousand", "million", "billion"): el evaluador convierte la predicción a la escala del Ground Truth antes de comparar. Por ejemplo, 1500 con scale="thousand" equivale exactamente a 1.5 con scale="million".
  • Porcentajes ("percent"): siempre deben expresarse de 0 a 100 (ej. 15.4 para 15.4%, nunca 0.154) y solo son compatibles con scale="percent".
  • Tolerancia numérica: se aprueba si el error absoluto es ≤ 0.01 o el error relativo es ≤ 0.001 (0.1%).
Ejemplo de normalización válida+1.0
GT: primary_value = 2.828, scale = "million"  |  Pred: primary_value = 2828, scale = "thousand" → Normalizado a 2.828 → CORRECT.
Ejemplo de error frecuente (percent_decimal)-1.0
GT: primary_value = 15.4, scale = "percent"  |  Pred: primary_value = 0.154, scale = "percent" → WRONG_VALUE (faltó multiplicar por 100).

4. Filtros y navegación del visualizador

  • ORIGEN (answer_from): indica dónde está la evidencia necesaria para responder: table (solo tabla), text (solo párrafos) o table-text (híbrido entre tabla y párrafos).
  • GROUND TRUTH: filtra entre casos resolubles (SOLVED) e irresolubles (ABSTAIN).
  • RESULTADO EVALUACIÓN: disponible al cargar un JSON de predicciones; permite aislar rápidamente Solo errores (-1.0 / -1.5), No óptimos (incluye abstenciones cautelosas) o un estado específico.
  • Atajos de teclado: ← / → (o K / J) para cambiar de caso, y S para ocultar o mostrar el panel lateral de casos.

5. Cómo leer los paneles y la comparación

  • Barra superior: muestra Score (puntaje neto acumulado / máximo posible), Accuracy (% de casos óptimos: CORRECT + ABSTAIN_ON_UNSOLVABLE), conteo por categoría y Tokens totales consumidos.
  • Ground Truth vs Predicción (lado a lado): compara fila a fila verdict, primary_value (mostrando el valor normalizado si difiere de escala), scale, derivation y error num. Las celdas resaltadas en naranja marcan exactamente dónde hubo discrepancia.
  • Tabla Financiera y Párrafos Narrativos: representan el contexto exacto enviado al agente en POST /solve. Usá el buscador superior derecho de la tabla para resaltar términos o cifras en ambos bloques.
  • Execution Trace: detalla cada llamada a herramienta (tool_name, tool_input, tool_output) para auditar qué recuperó el agente y qué expresión calculó.
  • Telemetría (usage): muestra tokens y llamadas LLM del caso; si total_tokens < 50, llm_calls < 1 o la suma no coincide, el evaluador marca Anomalía telemetría.
